# 06 MVP 設計與技術選型

## 1. MVP 要回答的問題（依優先順序）

| # | 問題 | 輸出 | 資料 |
|---|---|---|---|
| Q1 | 路網哪裡「疊床架屋」？ | 站位路線堆疊地圖、路段班次堆疊地圖 | 真實資料（公運處 blob） |
| Q2 | 哪些路線與捷運高度重疊？ | 各路線三種重疊度排行與地圖（幾何、站點、旅次） | 真實資料 ＋ mock（旅次） |
| Q3 | 各站在各時段的真實熱區與冷區？ | 分時段熱區圖、Gi\* 熱點與冷點 | mock，之後換成 TDX 票證資料 |
| Q4 | 哪些區塊適合導入 DRTS 或小型巴士？ | DRTS 適用分數地圖（H3 res 8） | Q2、Q3 ＋ 人口與地形 |
| Q5（加分） | 折返點是否適合讓駕駛休息？班表的休息時間是否足夠？ | 端點站設施評分、超過 75 分鐘沒有如廁機會的班次清單 | 真實資料（公廁、GPS）＋ 調查 |

## 3. 技術選型（建議）

| 層 | 選項 | 理由 |
|---|---|---|
| 資料擷取 | Python ＋ `requests`；TDX 用 `nycu-tdx-py` 或自己寫 OAuth | 公運處 blob 不需要金鑰，TDX 要 client credentials |
| 處理 | geopandas、shapely、h3-py、numpy、pandas | 標準組合 |
| 空間統計 | PySAL `esda`（Gi\*、Local Moran） | [V] https://github.com/pysal/esda |
| 路網與步行圈 | OSMnx 或 r5py | 步行等時圈 |
| GTFS | 由公運處 blob 自行轉成 GTFS，或用 TDX GTFS；再用 `gtfs_kit`、`gtfs_functions` 算路段頻率 | gtfs_kit 已遷移到 Codeberg |
| 視覺化（探索） | kepler.gl、QGIS、lonboard（Jupyter） | 快速驗證 |
| 視覺化（MVP） | **Streamlit ＋ pydeck**（最快），或 MapLibre GL JS ＋ deck.gl 靜態網站 | 前者開發快，後者容易部署成 GitHub Pages |
| 儲存 | GeoParquet，或 DuckDB（含 spatial 擴充） | 捷運 OD 每月約 300 MB，CSV 太大 |

## 4. 資料管線

```
[公運處 blob 快照] ──┐
[捷運出入口/路網] ───┼─► 正規化（站位、路線、站序、線形、班距）─► 重疊度模組 ─┐
[TDX GTFS/Shape] ───┘                                                    │
[mock 或 TDX 票證] ─────► 站點分時上下車 ─► 熱區、冷區模組（Gi*、H3）────────┼─► DRTS 評分 ─► 儀表板
[人口/信令/地形] ──────────────────────────────────────────────────────┘
[GetBusData 持續收集] ─► 場站與折返點推估 ─┐
[公廁/停車格位] ──────────────────────────┴─► 駕駛休息評分 ──────────────────► 儀表板
```

## 5. 里程碑（預研究建議時程，可以依團隊調整）

| 週 | 里程碑 | 交付物 |
|---|---|---|
| W1 | 資料取得與正規化；**送出 TDX 票證資料申請**；開始每分鐘收集 GetBusData、GetBusEvent | `data/` 結構、擷取腳本 |
| W2 | Q1、Q2：堆疊地圖與重疊度（加入路線別、步行距離） | notebook ＋ 靜態地圖 |
| W3 | Q3：用 mock 做熱區與冷區管線；年報 OCR 校準 | 熱區圖 |
| W4 | Q4：DRTS 評分；3 個示範區塊的方案（例如內湖科學園區通勤、山區冷區、捷運接駁缺口） | 情境比較表 |
| W5 | Q5：端點站設施評分（公廁 5 分鐘步行圈）；用 GPS 推估運轉時間第 95 百分位 | 折返點清單 |
| W6 | 儀表板整合、文件、對外簡報 | MVP demo |

## 6. 初步可以展示的示範區塊（依現有實測數據提出，待驗證）

1. **內湖科學園區瑞光路走廊**：單一站位停靠多達 42 條路線（含多條通勤專車），檢驗「供給集中，但離峰是否過剩」。
2. **忠孝幹線、310、46、88 等與捷運平行的路線**：站點重疊度上限 > 85%，檢驗旅次重疊度是否同樣偏高（依首爾經驗，可能大幅降低）。
3. **年運量最低的山區路線（小14、貓空、553 等）**：冷區轉型 DRTS 的候選。
4. **士林福林路、中正路走廊**（泰北中學、福林國小 33 條路線）：區間車與支線的整併。

## 7. 成功標準（MVP）

- 可以在地圖上切換時段，看到站位熱區與冷區的變化。
- 可以點選任何一條路線，看到三種重疊度與載客剖面。
- 可以調整門檻（重疊度 %、每班次人數），即時看到候選裁併或轉型的清單。
- 所有 mock 資料在畫面上都清楚標示。
- 換成真實資料時，只需要替換 adapter，不需要改分析程式。
