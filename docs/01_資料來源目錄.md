## 0. 一句話結論

- **逐站、分時的上下車刷卡資料確實存在**，在 TDX「票證服務」的「臺北市市區公車分時上下車人次資料」與「臺北市公車每日各站分時 OD 資料」，時間範圍 2018-01 至 2026-10。
- 但這些資料**不是開放資料**：每一項都要經過資料提供單位（臺北市政府）審核，而且每次申請要 500 點，免費方案每月只有 3 點。
- 因此 MVP 先用 **mock 資料**，資料欄位結構盡量對齊 TDX 票證資料，日後拿到真實資料就能直接替換。
- 申請流程本身就是研究計畫的一個工作項目，見 [08_問題與待辦清單](08_問題與待辦清單.md) 的 A1。

### A2. TDX 運輸資料流通服務：公車 API　P0（需註冊）

- 驗證方式：OAuth2 client credentials [V]
  - 取得 token：`POST https://tdx.transportdata.tw/auth/realms/TDXConnect/protocol/openid-connect/token`
  - token 有效期 86,400 秒，呼叫時帶 `Authorization: Bearer`。
- 不帶金鑰呼叫會得到 `401 Valid API Key Required` ✅。
- 訪客模式只能在瀏覽器使用，每個 IP 每天 20 次。[V]
- 方案與點數（https://tdx.transportdata.tw/pricing）[V]：

| 方案 | 月費 | 每月點數 | 速率限制 |
|---|---|---|---|
| Basic | 0 元 | 3 點 | 每把金鑰 5 次／分 |
| Bronze | 200–800 元 | — | 5 次／秒 |
| Silver | 1,000–4,750 元 | — | 10 次／秒 |
| Gold／Platinum | 更高 | — | 更高 |

- 點數計算：Basic 服務每 1,500 次呼叫或每 150 MB 扣 1 點；歷史資料每 10 次呼叫扣 1 點；票證資料每次申請 500 點。
- 學術單位與政府單位可申請 5 折。
- 每個會員最多 3 把金鑰。
- 規格文件：Swagger `https://tdx.transportdata.tw/webapi/File/Swagger/V3/2998e851-81d0-40f5-b26d-77e2f5ac4118`（v2，79 個路徑）。[V]

| 路徑（`/api/basic`） | 內容 |
|---|---|
| `/v2/Bus/{Route,Stop,Station,StopOfRoute,DisplayStopOfRoute,Shape,Schedule,DailyTimeTable,Operator,Vehicle,RouteFare,S2STravelTime,…}/City/Taipei` | 靜態資料 |
| `/v2/Bus/RealTimeByFrequency/City/Taipei` (A1) | 定時回報的車輛位置 |
| `/v2/Bus/RealTimeNearStop/City/Taipei` (A2) | 進出站事件 |
| `/v2/Bus/EstimatedTimeOfArrival/City/Taipei` (N1) | 預估到站時間 |
| `/v2/Bus/.../InterCity` | 公路客運 |
| v3：`/v3/Bus/Depot`、`/v3/Bus/Network`、**`/v3/Bus/DRTS/{Stop,Route,BookingRule,…}/City/{City}`** | 場站與 DRTS 的資料標準，**可以參考它的資料結構** [V] |

- ⚠️ **路線分屬不同機關**：臺北市聯營公車包含新北業者經營的路線，所以要同時抓 Taipei、NewTaipei、InterCity 三種，再用臺北市界裁切。
- ⚠️ 公運處 blob 的路線 ID（`UniRouteId`／`NId`）與 TDX 的 `RouteUID` 不同，需要建立對照表。

| 資料 | 臺北市 | 新北市 | 公路客運 |

| A2 歷史 `/v2/Historical/Bus/RealTimeNearStop/City/{City}` | 2023-12-17 起 | 2023-12-13 起 | 2024-11-21 起 |
| 靜態快照 `/v2/Historical/Bus/{Route,Stop,Shape,Schedule,…}/Date/{Date}/City/{City}` | 2024-01-02 起 | — | — |

- 以每 10 次呼叫扣 1 點計算，免費方案每月大約只能呼叫 30 次；**要分析一整年需要付費方案**。
- 替代做法：自己架排程，每分鐘抓公運處的 `GetBusData` 與 `GetBusEvent` 存檔，免費但只能從現在開始累積。

- 服務列表：`https://tdx.transportdata.tw/webapi/service?category=ticket` ✅（本 repo 實測共列出 16 項臺北市公車服務，`isNeedAccessReview = true`）

| 服務名稱 | 時間範圍 [V] |
|---|---|

| **臺北市公車每日各站分時OD資料 (O)／(D)** | 同上 |
| 臺北市公車分時旅運量資料 | 同上 |

- 格式為 CSV，更新頻率不定時。
- **欄位結構要登入後才看得到**，本研究尚未看到。
- 每次申請 500 點，至少要 Silver 方案；學術單位可申請 5 折。
- ⚠️ 媒體報導（iThome）[U] 指出，臺北公車因為分段收費，約九成乘客只刷一次，而且刷卡紀錄本身不含站位欄位，要和車機位置比對才能得到站位。所以 TDX 的逐站人次**很可能是推估值，不是直接觀測值**。

### A5. TDX 其他相關服務　P1

- GIS 服務（不扣點，只依流量計費）：
  - `/V3/Map/District/Boundary/{City,Town,Village}`：行政界線
  - `/V3/Map/Bus/Network/{Stop,Station,Route}/City/{City}`：公車路網
  - `/V3/Map/Road/Network/City/{City}`：道路路網
  - [V] 已在規格文件中確認
- 加值服務：[V] 已在服務列表中確認
  - `/V3/Map/Governance/RoadUnCoverage/Bus/City/{City}/TownCode/{TownCode}`：**公車服務未涵蓋率**
  - `/V3/Map/Governance/InAccessibility/Transit/Household/...`：**無大眾運輸可及的戶數**
  - 這兩項可以直接用來找 DRTS 候選區。
- 社經資料：`/v1/SocialEconomic/PopulationStats/Year/{Year}/City/{City}/Town/{Town}/Village`，村里人口。[V]
- GTFS：「取得GTFS檔案 v3」與「臺北捷運GTFS靜態資料」，0 點，需要登入。[V] 列表
- 第三方鏡像：jcanizalez/tdx-gtfs-mirror，每日更新的全國 GTFS，約 468 MB ✅（只查了檔頭，沒有下載）。
