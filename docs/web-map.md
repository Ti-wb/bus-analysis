# 前端地圖（Bus coming soon）

`web/` 是單頁地圖，呈現臺北市及周邊的公車路線、捷運路網，以及四種可切換的分析圖層：公車計畫班次網格、站點覆蓋、需求落差、村里年齡。可點選公車、捷運與 YouBike 查看站點及 350 m 年齡估算。用 React、TypeScript、react-map-gl（MapLibre GL JS）與 Vite 建置，輸出為靜態網站，不需要地圖金鑰或後端；底圖與路名使用 OpenFreeMap 公開圖磚，需連網。

品牌依 [`branding/BCS-Brand-Guidelines.pdf`](../branding/BCS-Brand-Guidelines.pdf)：介面色彩與字體用其中的 Web tokens（`--bcs-*`，Nunito＋Noto Sans TC 由 Google Fonts 載入），地圖上的資料配色不受影響。網站用的 favicon、App 圖示、分享圖與 logo 複製自 `branding/assets/`，放在 `web/public/` 與 `web/src/assets/`；素材更新時要一併替換。

## 執行

```bash
# 1. 由 repo 內資料產生前端圖層，輸出到 web/public/data/（不進 Git）
uv run scripts/build_web_data.py
# 2. 安裝前端套件並啟動開發伺服器（http://localhost:5173）
npm --prefix web install
npm --prefix web run dev
# 3. 型別檢查並建置靜態檔到 web/dist/
npm --prefix web run build
```

資料更新後重跑第 1 步即可。只檢查型別可用 `npm --prefix web run typecheck`。
村里年齡使用已提交的 `map-data/population/moi_village_age_2026-09.geojson.gz`；
先更新人口或里界時，依[清冊與站圈流程](moi-village-age-geography.md#抓取與離線重建)重新核對及巡檢，再建置前端。

## 底圖載入與復原

線上底圖在 12 秒內未完成載入時，會自動改用本地簡圖；本地簡圖保留已取得的道路、行政界與資料圖層，沒有線上底圖路名。切換後「使用本地簡圖」按鈕改為「重試線上底圖」，可在網路恢復後再試。關閉簡圖提示後，仍可從右下角「本地簡圖・底圖選項」重新開啟復原控制。

地圖區分載入中、可操作與載入失敗。部分圖磚或資料來源出錯時會保留已載入內容並顯示警告，不會重新顯示載入中；可選「重試地圖」。若本地簡圖仍超過 12 秒未完成、地圖初始化失敗或繪圖連線中斷，會停止載入提示並提供重試。重試與底圖切換保留目前鏡頭的位置、縮放、旋轉、傾斜及側欄留白，也保留選取與路線草稿；重新載入整個網頁則依各工具的儲存規則處理。

回歸狀態測試使用 `npm --prefix web run test:map`，既有 CI 的 `test:routes` 入口也會執行這組測試。產生前端資料並啟動開發伺服器後，可開啟 `http://localhost:5173/tests/mapRecovery.browser.html`，檢查實際 MapView 的載入、圖層警告、重試及完整鏡頭保留；加上 `?fault=style` 模擬外部樣式載入失敗，或 `?fault=webgl` 模擬 WebGL 無法初始化，再用測試頁的「解除測試限制」與地圖重試按鈕確認復原。加上 `app=1`（例如 `?app=1&fault=webgl`）可直接驗收 App 的 loading 與未套用草稿保留。這是僅供開發的測試頁，故障為模擬；正式頁面與真實網路仍須另行操作驗收。

站點卡復原以桌面寬度驗收：按「選取捷運站」與「保存站點卡」，展開設施後模擬 WebGL 中斷；「檢查重試按鈕」須通過，滑鼠可直接點擊重試。地圖就緒後按「檢查站點卡平移」，須保留同一張資訊卡、展開狀態，並隨標記平移；另以圖層警告切換本地簡圖重做一次。

## 面板與偏好

左側可直接切換站點覆蓋、公車班次、需求落差與村里年齡；目前分析的摘要與圖例優先顯示，補充路網圖例可展開查閱。班次保留小時滑桿與播放。半徑、權重等設定在頂部「偏好」側欄，按「套用設定」才生效：

- 分析圖層：站點覆蓋（預設）、班次網格、需求落差、村里年齡，四者擇一。
- 各圖層的設定：覆蓋的網格與半徑；班次網格的網格大小與日型；需求落差的時段、呈現方式與權重。
- 圖層顯示：公車路線、重要地點與類別、公車／捷運／YouBike 站點標記、底圖地名與道路標籤；覆蓋另有步行、騎乘與網格線開關。
- 跨市圖層：新北／跳蛙路網、里人口與年齡、道路速率快照及站間旅時；跳蛙篩選、人口著色方式與旅時日型也在「偏好」套用。
- 「恢復預設值」還原目前分析圖層以外的所有設定。

## 班次網格

班次以淺至深的青綠色階表示，越深班次越多；0 班為淺灰、班表缺漏為斜紋、無站牌為近透明底色。顏色不表示服務好壞，部分班表缺漏仍在格子提示中標示。分級門檻與計算方法維持原設定，不同網格尺寸或全日／小時不可直接比色。

探索頁現在讀取 `regional_bus_grid_{100,150,250,500}.json`，由 `scripts/build_regional_bus_grid.py` 對已保存且取得至尾頁的 TDX 臺北、新北、基隆、公路客運 StopOfRoute／Schedule 計算。依 RouteUID、SubRouteUID、方向去重，同一站位／附線不可因跨機關發布而重算；不同業者的班表只在官方明示時合併，缺少業者 ID 者暫計一次並標示不確定。未解析的班表是 null，不能當作零班。這些網格反映**計畫起站發車**，不代表實際經過該站或實際運量。

固定班表與班距的優先順序分別在每個業者內判斷，再加總各業者：例如甲業者 08:00 固定一班，乙業者 08:00–09:00 每 10 分鐘一班，08 時合計為 7 班。同一業者同一小時有固定班表時，才不再加入該業者的班距估算。

跨市網格 JSON 使用 `schema_version`、`dataset_id`、`metadata`、`records`；`metadata.grid_definition` 保存網格原點、間距、尺寸及欄位順序，`records` 保存精簡的每格數列。前端讀入時轉成共用地圖格式。單獨執行 `uv run scripts/build_regional_bus_grid.py` 會補上當下 UTC 建置時間，與來源更新時間分開。

資料產生後執行 `uv run scripts/review_regional_bus_grid.py`，由獨立巡檢程式從保存的官方來源重算班次與網格，核對來源、欄位、期間、筆數及加總；結果保存在 [`data/quality/regional_bus_grid_review.json`](../data/quality/regional_bus_grid_review.json)。更新來源或計算規則後須重新產生並巡檢；CI 在巡檢通過後才繼續建置，並保留當次報告 30 天。計算與巡檢回歸測試使用 `uv run python -m unittest discover -s tests -p 'test_regional_bus_grid*.py' -v`，前端讀取測試使用 `npm --prefix web run test:regional`。

250／500 m 網格涵蓋北北基行政範圍（新北含山區）；為避免 100 m 網格造成地圖過載，100／150 m 僅納入公車站位約 350 m 周圍的網格，其餘區域是「不在細尺度顯示範圍」，不能解釋為零班。行政界版本及各發布端點時間可能不同。原 `bus_grid_*.json` **保留給臺北市路線方案工具**，需求落差仍依 `transport_need_250.json` 的臺北市模型。原圖色階尚未對全北北基重新校準，不適合直接以顏色做跨城市量化比較。

舊臺北市路線工具仍採下列地方 feed 計算方式：

- 約 100、150、250、500 m 四種經緯度方格（以北緯 25.05° 換算），只保留與臺北市界相交的格子；預設 500 m。小格子較能看出沿路廊分布，但格內站牌少、數值較跳動；各尺寸色階依其數值分位另訂，不同尺寸的顏色不能直接比較。
- 每格的值是格內站牌所屬附線，在該小時的計畫發車數加總；同一附線在同一格只算一次，不分方向。
- 固定班表優先；同一小時沒有固定班表時，用班距區間換算（最長、最短班距平均）。
- 平日以週三班表代表，週六、週日分開計算；「全日」是 24 小時加總。
- 格子狀態：無站牌、有班表、部分附線缺班表（數值偏低，滑鼠移上去會提示）、全部附線缺班表（斜紋，不是 0）。

## 站點覆蓋

依 Penpot 設計稿第 04 頁「步行 350 m × YouBike 1 km」。開啟網站預設即為站點覆蓋。

- `coverage_50.json`、`coverage_100.json`、`coverage_200.json` 分別是約 50、100、200 m 方格，各自從格心量距離，只保留格心在臺北市內的格子；每格記錄格心到最近公車站位、捷運車站、YouBike 站的直線距離（TWD97 平面公尺，以 10 m 為單位，超過 3 km 記為上限）。預設 100 m。
- 步行到站（橙色）：公車、捷運、YouBike 各有半徑（100–1000 m，預設 350 m），可取消勾選不計入；格子取各站種中最靠近站心的一段。YouBike 騎乘（藍色）只看 YouBike 站，半徑 500–3000 m，預設 1 km。兩層可同時開，重疊處優先顯示步行色，不混成第三種顏色；關閉步行層即可查看完整騎乘範圍。
- 半徑內依距離分 5 段，越靠近站點越深；滑鼠移到格子上會顯示三種站點的最近距離。
- 設定寫進網址（`mode=coverage`、`cov`、`st`、`walk`＝公車,捷運,YouBike 半徑、`ride`、`cg`＝網格公尺；關閉時才寫 `gl=0`、`lbl=0`），可直接分享。舊連結的單一 `walk` 值會套用到三種站點。
- 直線距離沒有計入路網、河川、鐵路阻隔，也不代表班次多寡或即時有車；捷運以車站點位計算，不是出入口；YouBike 只有臺北市站點，市界附近會高估距離。

## 需求落差

依 [12 運輸需求權重方法](12_運輸需求權重方法.md) 第一版，在「偏好」的「分析圖層」選「需求落差」。資料第一次切換時才載入（約 1.2 MB）。

- 250 m 網格，時段分平日早峰、離峰、晚峰、晚間與週六、週日。
- 「需求 × 供給」用 3×3 雙色：需求、供給各依同時段排名分三等分，橘色偏需求高供給低，藍色偏供給高；「落差值」用藍—淺中性—橘色階顯示需求排名減供給排名，淺色只表示排名接近，不代表供需平衡。四類摘要另以排名 50% 切分，不與九宮格三等分混用；補強候選、供需皆高、供給偏高、供需皆低都不代表已證實不足或過量。
- 需求權重（居住人口、重要地點、捷運活動）可在「偏好」以滑桿調整，套用後前端重算排名；預設 50／30／20。深框是預設權重下穩健的優先格，調整權重後不顯示。
- 斜線是附近有附線缺班表（供給為下限）；淡灰是人口少於 100 且附近無主要地點，不排名。
- 滑鼠移到格子上，會列出需求三項的排名與貢獻、供給排名，以及人口、地點分數、捷運進出量、加權班次。
- 設定寫進網址（`mode=need`、`band`、`nview`、`nw`）。

## 站點資訊

依 Penpot 第 04 頁「站點資訊 / *」與「站點 Focus / 01 公車・周邊350m＋5條路線」，點選或搜尋公車站會進入 Focus：左側顯示本站周邊 350 m 近鄰詳圖與全部服務路線，主地圖縮放至路線總覽，人口與設施卡固定於右側。橙色覆蓋僅來自本站與目前開啟服務路線的公車停靠站；其他路線暫時灰化，全域站點覆蓋、班次及需求網格暫時隱藏。返回探索、資訊卡關閉或 Escape 會還原進入前的視野與原有偏好。捷運與 YouBike 沿用站點旁的資訊浮卡。

- 服務路線以 `route_ids` 精確連接，不以名稱相近推定。側欄不限制五條；缺線形仍列名並標示，不提供地圖定位，但可切換其已知停靠站與覆蓋。
- 點路線可定位整條主線，眼睛按鈕同步切換路線、停靠站與覆蓋；「路線總覽」依目前可見路線重新取景，「350 m 周邊」或近鄰詳圖回到本站。「全部顯示」可恢復隱藏路線。
- Focus 覆蓋從目前開啟服務路線的停靠站重新計算格心最近距離，另固定納入本站；附近無關公車站、捷運與 YouBike 不參與計算。半徑固定 350 m，沿用覆蓋網格大小與格線偏好，以橙色五段顯示直線距離；跨市已知停靠站也保留。全部路線關閉時只保留本站覆蓋，距離未計道路或河川阻隔，並非班次熱度。
- 清單班次為代表平日各附線的全日計畫發車加總，同主線各方向線形不重複加總；不代表本站到站時刻。近鄰圖依實際道路、路線及站點繪製，站數依來源站位計算。

站點分析範圍固定為直線 350 m，與覆蓋圖層半徑分開；點另一站替換內容。

- 統計區人口與戶數：`station_catchments.json` 以各站實際顯示點位、TWD97 平面公尺計算；統計區部分在圈內時依面積比例分攤。
- 統計區年齡分布：2024-12 最小統計區五歲年齡組合併為 **0–14、15–24、25–64、65 歲以上**，沿用同來源人口的面積比例分攤；整數化後四組加總等於範圍人口，比例四捨五入。有統計區缺年齡資料或沒有人口時顯示缺資料狀態。這四組不與下列 2026-09 村里分組混用。
- 村里年齡分攤：新 `station_age_catchments.json` 使用 2026-09 逐歲戶籍人口與已核對的北北基完整里界，可切換三段／細分年齡。全量有 38,372 個公車站碼（5,376 個原臺北站碼＋32,996 個跨市站碼，保留來源座標變體）、154 捷運站及 1,822 YouBike 站，共 40,348 站；各站產生 200／350／500 m 三個半徑，浮卡固定使用 350 m。三種站點沿用各自原始 ID，不借用鄰近站的人口。
- 年齡站圈完整時顯示全齡估算及分組比例；`partial` 只顯示已知部分與各組涵蓋面積，不以部分人口當成完整比例分母。全齡缺值、某組逐歲缺值、未匹配、幾何衝突及界外面積各自保留；未知不補零。
- 所在里人口與年齡：另列站點所在里的官方統計，與 350 m 範圍估算分開；未找到已核對里界或人口時顯示缺值，不套用示意比例。
- 附近重要設施：依「偏好」已選的重要地點類別，按直線距離排序，先列最近三處，可展開全部；候選位置未去重。
- 「站點與周邊交通」可展開路線、班次、停車格與周邊站點數等既有資訊。

統計區人口／戶數及四組年齡是 2024-12、2015 年版邊界，僅臺北市；另列的村里年齡分攤是 2026-09 人口、2026-08-17 主里界，涵蓋北北基。**兩者不能直接比較增減或混算分組與比例**；各自的年齡比例使用各自來源的全齡分母。兩者均不是白天活動人口或搭乘量，相鄰站點範圍重疊，人口不可加總。人口與年齡各有載入失敗重試，設施仍可查閱。來源核對分別見[舊統計區巡檢](../data/quality/web_station_catchments_review.json)與[年齡站圈獨立重算](../data/quality/station_age_catchments_review.json)。

## 村里年齡

在「偏好 → 分析圖層」選「村里年齡」並套用，或按左側「查看村里年齡」。左側可選三段／細分組及年齡層，地圖以該組占整村戶籍人口的比例上色；固定區間為 0–10%、10–20%、20–30%、30–40%、40% 以上。灰色表示未匹配、缺值或總人口為 0 而比例無分母，不能當成零人口。

點選里界或使用「查詢村里」下拉選單，可查看原始碼、兩端名稱、人口／清冊月份、里界版本與核對狀態。鍵盤可先以方向鍵移動地圖，再按 Enter 查詢畫面中央村里；Escape 關閉。圖層涵蓋北北基全部 1,677 個官方圖形，部分在初始視野之外；全國 7,781 村里的核對摘要另列於左側，並不宣稱全國地圖或站圈已上線。

顯示圖形僅為縮小檔案而簡化；站圈計算使用未簡化完整里界。年齡圖層按需載入；站卡依原始站種／站碼選取 `station_age_catchments/part-00.json` 至 `part-31.json` 的其中一片，避免一次載入全量。每片優先讀 `.gz`，最大約 264 KB（JSON 約 3.9 MB）；瀏覽器無解壓支援或壓縮檔不存在時使用同內容的該片 JSON，其他載入或格式錯誤顯示重試。網址的 `mode=village_age`、`aset`、`ag` 保留分組與年齡層。

全國有 17 個名稱差異未核實，Sanhe 附層日期不明且與六個主層村里重疊；這 24 村的 45,064 人保留來源數值、排除分攤。206 個未編定區塊不補人口。完整資料與覆蓋率契約見[清冊、里界與站圈說明](moi-village-age-geography.md)。

## 限制

- 以起站發車時刻歸入小時，沒有加上行駛到該格的時間。
- 舊臺北市路線工具只使用臺北市公共運輸處 feed；新北市專屬路線不在內，市界附近會低估。
- 這是計畫供給，不是實際發車或載客量；也不代表步行可達性。
- 捷運沒有班次資料，只呈現路網；捷運站與公車站牌沒有做 ID 對應。

上述三種分析中，**探索頁班次網格已改用北北基 TDX 模型**；站點覆蓋、需求落差、路線方案工具仍維持原臺北市模型。新北／跳蛙路網、北北基里人口及旅時／速率是可獨立開關的補充圖層，不會自動改變需求落差、覆蓋與路線工具數值。開啟里人口時暫藏分析填色，關閉後恢復原設定；里人口依人口月檔與保留的官方里界版本核對，尚不能據此證明該月份的邊界完全相同。

補充圖層由 `scripts/build_web_supplemental.py` 產生，已納入一般建置入口；也可單獨執行 `uv run scripts/build_web_supplemental.py`。輸出 `regional_bus_routes.geojson`、`regional_bus_stops.geojson`、`villages.geojson`、`traffic_sections.geojson`、`bus_travel_times.geojson`、`supplemental_manifest.json` 至 `web/public/data/`，不進 Git。各檔保留來源路徑、網址、來源時間、單位與限制；獨立巡檢放在 `data/quality/`。來源異常或資料載入失敗會顯示狀態並可重試。

獨立重算使用 `uv run scripts/review_web_supplemental.py`，結果為 `data/quality/web_supplemental_review.json`；除整理後資料外，需保留道路來源 OpenAPI 與原始回應快照。大型原檔不進 Git，網頁建置不依賴這些原檔；巡檢結果只對應所核對的快照，更新來源後需重做。

## 部署（GitHub Pages）

`.github/workflows/deploy-web.yml` 在 `main` 的前端程式或來源資料變更時，產生地圖資料、型別檢查並建置，再發布到 GitHub Pages；也可在 Actions 頁面手動執行。相關 PR 只建置不發布，用來提早發現錯誤。

網址為 <https://bus.tw.pe/>。Pages 來源（GitHub Actions）與自訂網域都在 **Settings → Pages** 設定，需 repo 管理員權限；DNS 以 CNAME 指向 `ti-wb.github.io`。建置使用相對路徑，換網域不用改程式。

### 快取與 Cloudflare

GitHub Pages 對所有檔案固定回傳 `Cache-Control: max-age=600`，無法調整。程式檔名每次建置都會改變，但 `data/` 的檔名固定，所以前端讀資料時會在網址加上建置版本 `?v=…`：CI 用 commit 前 12 碼，本機 `npm run build` 用建置時間，`npm run dev` 不加。部署後新程式只會讀到同一次建置的資料，不會拿到前一版快取。

網域經 Cloudflare 代理。`.json`、`.geojson` 不在 Cloudflare 預設快取的副檔名內，沒有規則時只會轉送（`cf-cache-status: DYNAMIC`）。在 Cloudflare 後台 **Caching → Cache Rules** 依序新增：

| 規則 | 條件（Edit expression） | 設定 |
|---|---|---|
| 帶版本的資料 | `starts_with(http.request.uri.path, "/data/") and http.request.uri.query contains "v="` | Eligible for cache；Edge TTL：Ignore cache-control header，1 年；Browser TTL：Override origin，1 年 |
| 建置產物 | `starts_with(http.request.uri.path, "/assets/")` | 同上 |
| 不帶版本的資料（選用） | `starts_with(http.request.uri.path, "/data/") and not http.request.uri.query contains "v="` | Eligible for cache；Edge TTL：Use cache-control header if present（沿用 10 分鐘）；Browser TTL：Respect origin |

- **不能清掉的設定：** Cache key 保留預設的完整 query string，不可開啟「忽略 query string」，否則各版資料會共用同一份快取。
- **其他路徑不設規則：** `index.html` 等路徑維持預設。首頁必須在部署後盡快更新，才會指向新的程式與版本號。
- **部署後不需清快取：** 每次部署的網址都會改變。
- **設定後檢查：** 對同一網址連續送兩次 `curl -sI "https://bus.tw.pe/data/villages.geojson?v=check"`，第二次應出現 `cf-cache-status: HIT`。
